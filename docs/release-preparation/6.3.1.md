## Candidate validation and publication boundary

Run `npm run release:check` and `npm audit --audit-level=high` for the versioned
candidate. Record exact-commit results, CI, artifact integrity, and Code Review
on the release-preparation PR before merge. The candidate requires its own
exact-SHA CI and Code Review; the source checks above do not replace them.

Before tagging, verify the chosen version remains unused and the reviewed
release source is on protected main. Use a new annotated immutable tag only
after release authorization. An accepted npm stage consumes the version; a
pre-stage failure may be rerun against the same tag, while post-stage recovery
requires a fresh reviewed version.

The operator's npm stage approval is the publication boundary. Verify the live
canonical package and exact staged-artifact integrity before creating its
GitHub Release, synchronizing the site, announcing publication, closing issues,
or changing consumer pins.
