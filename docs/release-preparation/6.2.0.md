## Publication boundary

The feature and preparation must merge through protected pull requests. Before
tagging, confirm the exact release source is on main, its CI/review evidence
is complete, the version is unused publicly and in staging, and the protected
npm environment and npm Trusted Publishing settings match `docs/RELEASING.md`.

A tag triggers verification and immutable npm staging. Stage acceptance is not
publication: the operator must inspect and approve the stage. No announcement,
issue closure, GitHub Release, dependent pin, or website synchronization occurs
until the canonical live package and integrity are verified.
