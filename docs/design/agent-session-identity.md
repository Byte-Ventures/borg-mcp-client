# Agent Session Identity Decision

`resolveAgentSessionIdentity()` returns `known` with an opaque, harness-prefixed conversation id, identity source, and observation time, or `unknown` with a bounded reason. Only ARRIVAL suppression consumes the identity; stream status displays it. It never supplies a credential or influences authorization, stream ownership, or liveness. Native conversation ids distinguish new conversations, not a process restart that explicitly resumes an existing conversation. No process identifier contributes to the mechanism.

## Verified Sources And Boundaries

**Claude Code.** The [official hook reference](https://code.claude.com/docs/en/hooks#sessionstart) defines `session_id` as the current session identifier and SessionStart sources including startup, resume, clear, compact, and fork. It documents hook stdin, but does not promise that `CLAUDE_ENV_FILE` values reach MCP children; that file is for subsequent Bash commands. Borg's existing Claude launch paths use `withAgentRuntimeEnv()` in `src/claude.ts` and `src/assimilate-cmd.ts`, and Claude inherits that environment into hooks and MCP children. Each launch now adds an independent random correlation, following the existing OpenCode correlation pattern. `src/regen.ts` records the native id, correlation, and hook observation time before requesting cube orientation. The reader accepts only a matching correlation from this child, preventing stale prior-launch state from masquerading as a current session. A missing or malformed source is unknown. A different launch writing the same worktree file makes the displaced launch unknown. Claude identity can be stale after a resume whose SessionStart hook failed. This accepted limitation requires a future harness-to-MCP per-call session handoff to eliminate; timing heuristics would incorrectly reject normal reconnects.

**Codex.** `src/codex-app-server.ts` exposes `thread/loaded/list` and `thread/read`, including id, ephemeral, threadSource, and source. `src/codex-wake-resolve.ts` documents the Borg-owned per-launch socket and the eligibility exclusions. Identity resolution uses that socket but does not reuse wake selection's recency fallback: exactly one eligible user thread is required. An unreadable candidate may conceal another user thread, so it makes the result unknown. MCP reconnects retain the native thread id; a new conversation changes it. System ephemeral and subagent threads never identify the session.

**OpenCode.** `src/opencode-plugin.ts` adds launch correlation metadata to the initial human message. `src/opencode-drone.ts` finds exactly one metadata match and persists the binding for the MCP child. Identity resolution reads this binding and verifies its session against the same correlation search; it does not claim or rewrite the binding. Missing or changed ownership, multiple metadata matches, and unseen root sessions are unknown. This is narrower than injection's `/new` heuristic. Reconnecting restores the same identity; a newly correlated conversation produces a different id.

## Verification And Observability

`__tests__/agent-session-identity.test.ts` starts separate client fixture children for reconnect and new-conversation cases. Claude exercises the real `borg-regen` stdin entrypoint and persisted state. OpenCode uses its real binding writer and HTTP reader against a fake session server. Codex exercises the real response adapter with fixture RPC responses, not a live app-server or TUI. Each child checks runtime process-id reads, and a source check covers identity-module initialization. Handler tests verify that one observation feeds both suppression and successful recording and that stream status displays source, id, and observation age. These fixtures verify Borg's handoff behavior, not live vendor-CLI lifecycle behavior. Local history retains one id per announced cube/drone/session; unknown observations never erase known history.
