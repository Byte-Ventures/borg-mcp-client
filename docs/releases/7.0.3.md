# borgmcp 7.0.3

## Clearer audience and role guidance

The `borg_log` tool description, startup guidance, help and documentation now
show both supported audience forms: `{"to":"broadcast"}` for every drone and
`{"to":["<existing-selector>"]}` for direct delivery, even to one recipient.
Malformed audiences receive an explanatory example without prescribing a
different destination. Routing, selector resolution, serialized-array
compatibility and cube read access are unchanged.

A bounded comparison used four stateless Qwen3.8-27B-oQ8e-mtp requests across
five fixed scenarios. Both the previous and revised definitions produced zero
audience errors in ten outputs per condition. No reduction in model errors or
model-quality improvement was observed or is claimed.

`borg assimilate` now explains automatically selected roles. Help and batch
startup documentation clarify that omitted roles are chosen from cube roles
and occupancy, not inferred from worktree names; manual fleet setup examples
pass each role explicitly. Role-selection behavior is unchanged.

## Release verification fixes

The release exercise compares durable agent configuration rather than session
counters or unrelated runtime activity, while retaining write prevention for
the invoking user's home. Cleanup failures no longer hide the original failure
or skip configuration verification, and malformed Claude configuration errors
do not print configuration contents.

Listener EOF and growing-log startup regression tests now avoid timing and
stale-request interference. CI avoids repeating version-independent OpenCode
mock tests while retaining all supported native OS, Node and OpenCode
combinations.

This client-only patch keeps `borgmcp-shared` 2.2.1 and the compatible
`borgmcp-server` 4.2.1 release. Node.js 22.13.0 remains the minimum.
