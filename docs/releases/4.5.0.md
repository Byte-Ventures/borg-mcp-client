# borgmcp 4.5.0

- On supported POSIX filesystems, an OpenCode startup identity failure is now written to a mode-0600 diagnostic file under the private config root, and `borg doctor` surfaces the persisted diagnostic. Component tests verify the persistence and doctor seams; this release does not claim a live OpenCode-server journey or Windows-equivalent permission behavior (#515).

- For public repositories, assimilating into a cube that already has an active seat from a different clone family now emits a warning and continues. Private repositories already distinguish clone families through their local repository identity and are unchanged (#263).

- Terminal-title rendering now sanitizes server-derived drone labels and cube names before they reach direct terminal control sequences, macOS AppleScript literals, or Linux shell commands. This is low-severity defense-in-depth hardening for terminal display output (#19).
