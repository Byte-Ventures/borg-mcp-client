# borgmcp 6.3.0

Choose one agent CLI for a whole batch of saved drone worktrees:

```sh
borg launch-all --cli opencode
```

Use `--cli claude` or `--cli codex` for the other supported agents. Both
`--cli opencode` and `--cli=opencode` work with a cube name, `--only`, and the
existing launch options. For one drone, use
`borg launch <drone-label-or-id-prefix> --cli opencode`.

## Batch CLI selection

- The selected CLI reaches tmux, terminal launches, and the default split
  between worker drones and the human-seat drone.
- Each launched worktree remembers the explicit choice. Without `--cli`,
  each worktree continues using its saved choice. Concurrent launches preserve
  every preference update and unrelated worktrees' existing choices.
- An unavailable CLI stops an actual batch launch before any windows or
  launch markers are created. The command returns a failure status.
- `--dry-run` previews the selected CLI without changing preferences.
  `--mode pastelist` prints commands containing the choice; preferences change
  only when those commands run. Both work before the chosen CLI is installed.
- Drone identity checks, filtering, and live-session skips still apply.

## Dependency update

Updates the SDK's transitive `@hono/node-server` dependency to 2.1.5, addressing
the static-path middleware bypass advisory GHSA-rmxm-3fg6-px4f.

## Upgrading

Run `borg update`. The Node.js minimum remains 22.13.0 and the shared contract
remains pinned to `borgmcp-shared` 2.2.0. No server or shared-package release is
required for this client change. OpenCode 1 and OpenCode 2.1.2 or newer remain
supported.
