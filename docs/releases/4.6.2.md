# borgmcp 4.6.2

- OpenCode binding identity is now one identity per process: the session binding is keyed by a per-launch correlation shared by the launcher and the MCP child; the placeholder→resolved handoff is a mutually exclusive claim; a different cube or drone cannot consume the binding; the diagnostic log is keyed by the normalized worktree (#536).

- An OpenCode child that exits before readiness (for example the probed port was taken before it bound) is retried up to three times, each attempt with its own launch trust; `--port`, `BORG_OPENCODE_PORT` and the consumer URL are rebuilt together; spawn errors keep their code and signal and the missing-OpenCode diagnostic is preserved; the MCP consumer stays fail-closed without a propagated port (#298).

- Per-worktree OpenCode launch access (`.opencode/opencode.json`) is repaired on every launch, not only at assimilation — a bare launch that had to ask which CLI to use previously left the seat unauthorized and its wakes undelivered; the write refuses path substitution (a symlinked `.opencode` or `opencode.json`) and aborts before spawn; a rejected prompt now surfaces as a degraded `borg_stream-status` verdict with a `borg_read-log unread_only=true` recovery pointer (#346).

- No protocol change; no server change required.
