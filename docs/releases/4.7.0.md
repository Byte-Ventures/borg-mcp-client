# borgmcp 4.7.0

- Adopts `borgmcp-shared@1.1.0` and protocol tag 13. Cube creation now sends canonical named templates rather than the removed legacy `default` seed. This release requires `borgmcp-server` 3.3.0 or later.

- Migrates tag-12 local state during upgrade. Legacy `default` repository associations are removed so the client can re-resolve authoritative association state from the server without mislabeling the cube. Pending cube-create records migrate from version 2 to version 3: named-template retries preserve their original idempotency keys, while legacy-default retries receive fresh named-template requests so repository homing can resolve a response-lost create.

- Adds `borg upgrade` as an exact alias for the existing `borg update` command, including identical help, validation, confirmation, registry provenance, install, and exit behavior (#471).

- Repository discovery now reports Git execution, query, and canonical-path failures instead of misclassifying them as a non-repository working directory (#531).

- Enables TypeScript unused-symbol checks, derives client variants from canonical domain types, and removes retired postinstall, active-cube, and persistence-copy seams (#529, #530, #532, #533).
