# borgmcp 7.0.2

## Codex launch policy compatibility

Existing Codex tool settings such as `borg:read-log` no longer require manual
duplication before launching Borg after the underscore tool-name update. Borg
adds the matching canonical or legacy name to temporary launch settings,
preserving the existing per-tool settings and enabled/disabled lists. Saved
configuration files remain untouched. Conflicting settings and ambiguous
patterns still require review.

Both `borg launch` and `borg assimilate` pass the resolved Borg policy to the
private Codex server that runs MCP tools. Selected profile and project settings
retain server enablement, default approvals and tool lists even when no names
need migration. Borg checks the server's effective configuration before launch.
Native defaults and empty tool tables are handled without discarding restrictive
empty allowlists.

The existing coordination approval override remains separate;
`--no-borg-approval-override` continues to preserve approval requirements.

This client-only patch keeps `borgmcp-shared` 2.2.1 and the compatible
`borgmcp-server` 4.2.1 release. Node.js 22.13.0 remains the minimum.
