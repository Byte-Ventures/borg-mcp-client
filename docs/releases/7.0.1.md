# borgmcp 7.0.1

## Reliable OpenCode 2 batch startup

Starting several drones with `borg launch-all --cli opencode` could hang or
fail while OpenCode upgraded its shared session database. Borg now queues
OpenCode 2 startup so each instance completes initialization before the next
begins. Once ready, the drones run concurrently.

If a Borg launcher closes or crashes during startup, its supervisor stops the
native OpenCode process before admitting the next launch. This prevents a
relaunch from racing migrations that are still running in an orphaned process.
Startup errors also distinguish timeouts, early process exits, and failed
readiness or identity checks.

Saved OpenCode sessions are preserved. OpenCode 1 remains supported. This patch
uses the same `borgmcp-shared` 2.2.1 dependency and compatible `borgmcp-server`
4.2.1 release as 7.0.0. Node.js 22.13.0 remains the minimum.
