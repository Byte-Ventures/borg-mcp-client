# borgmcp 6.0.1

This release fixes the order of `borg representative hermes-plugin install`. On 6.0.0, with two gateway DMs and three prepared worktrees, install asked the operator to pick a DM and confirm it `[y/N]`. Only after that did it refuse because several worktrees were prepared, and it printed a bare path list with no command to retry. Merged since 6.0.0: #601.

## Fixed

- **Install now runs as plan, validate, ask, apply.**
  - **Plan:** it lists every candidate worktree and conversation, and builds the exact values it would write.
  - **Validate:** it checks every candidate's plan with the same checks the writes apply, before any question. These are the value encoding (for example, a path containing a newline), the gateway DM key and the absolute `borg` path. The same pass also checks, read only, whether `plugins`, `config.yaml`, the backup directories and Borg's state path are usable.
  - **Ask:** only then does it ask, at a terminal.
  - **Apply:** it writes. After a question, install can stop only on an invalid or declined answer, a Hermes command's reply, or a write that fails.
- **When a selection is needed, install asks at a terminal**: for the worktree when several selectable worktrees are prepared, then for the DM, then for the `[y/N]` confirmation (default no). A `--worktree`, or a configured worktree that is still prepared, and a `--session-key`, or a configured valid DM key, are reused without a question, including without a terminal and on `borg update`.
- **Candidates that would fail are not offered.** They are shown as not selectable, with the reason. A single selectable worktree is used without a question.
- **Without a terminal (including `borg update`), a selection that is still needed is refused with exact retry commands.** Ambiguous worktrees get one `borg representative hermes-plugin install` command per selectable worktree, keeping `--hermes-home` and a given `--session-key`. An unconfirmed DM gets one command per candidate with `--session-key`, keeping `--hermes-home` and a given `--worktree`. Every value in these commands is shell-quoted.
- **Control, C1 and bidi characters are removed from:** displayed worktree and `borg` paths, the planned configuration values, and failure and rollback text (which can quote Hermes config values or replies). Other displayed paths, such as the Hermes home and the backup path, are printed as they are.
  - Retry commands are printed separately, with their exact bytes, so they round-trip even when a path contains a newline or other control characters.

## Upgrading

1. Run `borg update`.
2. If a 6.0.0 `borg representative hermes-plugin install` stopped before it finished, run it again. A 6.0.0 run that refused on the worktrees had not written Borg's plugin files, Hermes configuration or activation record. Hermes's own startup maintenance, which runs with its `config get` commands, may still have run.
3. The shared contract pin is unchanged: `borgmcp-shared` 2.2.0.
