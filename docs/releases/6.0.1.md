# borgmcp 6.0.1

This release fixes the order of `borg representative hermes-plugin install`. On 6.0.0, with two gateway DMs and three prepared worktrees, install asked the operator to pick a DM and confirm it `[y/N]`. Only after that did it refuse because several worktrees were prepared, and it printed a bare path list with no command to retry. Merged since 6.0.0: #601.

## Fixed

- **Install now runs as plan, validate, ask, apply.**
  - **Plan:** it lists every candidate worktree and conversation, and builds the exact values it would write.
  - **Validate:** it checks every candidate's plan with the same checks the writes apply, before any question. These are the value encoding (for example, a path containing a newline), the gateway DM key and the absolute `borg` path. The same pass also checks, read only, whether `plugins`, `config.yaml`, the backup directories and Borg's state path are usable.
  - **Ask:** only then does it ask, at a terminal.
  - **Apply:** it writes. After a question, install can stop only on an invalid or declined answer, a Hermes command's reply, or a write that fails.
- **At a terminal, install asks for the worktree** when several are prepared, then for the DM, then for the `[y/N]` confirmation (default no).
- **Candidates that would fail are not offered.** They are shown as not selectable, with the reason. A single selectable worktree is used without a question.
- **Without a terminal (including `borg update`), install refuses with exact retry commands.** Several prepared worktrees get one exact `borg representative hermes-plugin install` command per selectable worktree. Each command keeps `--hermes-home`, and `--session-key` when one was given, and every argument is shell-quoted.
- **Displayed paths and error text are cleaned of control, C1 and bidi characters.** This covers worktree paths, planned values, and rollback and failure text that quotes Hermes config values or replies.
  - Retry commands are printed separately, with their exact bytes, so they round-trip even when a path contains a newline or other control characters.

## Upgrading

1. Run `borg update`.
2. If a 6.0.0 `borg representative hermes-plugin install` stopped before it finished, run it again. Install writes nothing before its checks and questions pass, so a stopped 6.0.0 run that refused on the worktrees changed nothing.
3. The shared contract pin is unchanged: `borgmcp-shared` 2.2.0.
