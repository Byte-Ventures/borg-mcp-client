# borgmcp 7.0.0

Borg now advertises MCP tool names with underscores throughout, including
`borg_read_log`, `borg_describe_tool`, and `borg_representative_send`.
This fixes OpenCode 2 Code Mode calls that could parse a hyphenated name as
JavaScript subtraction and throw `ReferenceError: Unknown identifier 'log'`.

## Tool catalog migration

The advertised catalog change requires a major version. Before upgrading,
follow [the tool-name migration guide](../TOOL_NAME_MIGRATION.md) to give both
spellings equivalent restrictions in host policies and tool-hook matchers.
OpenCode's ordered permission rules need adjacent equivalent pairs. Borg's
Claude Code, Codex, and OpenCode launch paths check exposed policies and refuse
launch when equivalence cannot be established.

Restart or reconnect MCP servers and rediscover their tools after upgrading.
Only canonical names appear in discovery. A closed set of legacy aliases still
reaches the same handlers inside Borg; a strict host can reject an unadvertised
alias before forwarding it. Reinstall the bundled Hermes plugin to update its
tool calls. Saved roles, logs, and session history are preserved.

## OpenCode compatibility

OpenCode 1 and 2 remain supported. OpenCode 2 startup now gives cold configuration
and plugin initialization one shared 60-second deadline, then restores ordinary
runtime limits before TUI attachment and kickoff. Failed startup is cleaned up
before a kickoff can be sent.

## Coordinated packages

This release pins `borgmcp-shared` 2.2.1 and pairs with `borgmcp-server` 4.2.1.
The server's built-in guidance uses the same canonical names. Tool arguments,
result schemas, server authorization, and protocol version 14 retain their
current behavior. Node.js 22.13.0 remains the minimum.
