# borgmcp 8.0.0

## Breaking compatibility

This release requires protocol 15, `borgmcp-shared@3.0.0`, and the matching
`borgmcp-server@5.0.0`. Upgrade the server before the client. Protocol 14 peers
are refused before credentials are sent; there is no compatibility fallback.

## Failed attachment recovery

After an attachment failure, run the exact printed command from the original
source or preserved worktree:

```text
borg recover-attachment --host <endpoint> --attempt <uuid>
```

Recovery reuses the original stored bearer, drone, session, and cursors. If that
bearer is missing or replaced, explicit `--retire` confirmation can retire only
the failed pending operation; non-interactive retirement also requires `--yes`.
Newer connections and preserved worktrees are not overwritten or removed, and
no agent is launched. An absent reserved target is preserved by default, not
silently recreated. Credentials are never restored from a recovery handle.

An already finalized attachment whose local connection was subsequently reset
requires operator cube-management cleanup. A lost journal cannot be guessed or
reconstructed; losing only `seats.json` does not invalidate surviving parent
enrollment credentials.

## Verification boundary

Published 7.0.3-written parent credentials, pending records, bound pending records,
and active bindings were verified against the new reader, reuse, reset, and
refusal paths. Existing CI exercised the built client against public server
5.0.0, including printed recovery commands, durability and acknowledgment loss,
replacement preservation, and explicit stale-lock crash remediation.

The installed public-client recovery/crash journey and affected site updates
remain release close-out checks. This preparation does not claim completion of
the full recovery rollout.
