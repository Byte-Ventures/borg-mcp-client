# borgmcp 4.3.0

- `borg_create-cube` now creates a repository-bound cube from an explicit repository identity, making the tool usable over MCP where it previously failed. It takes a required `repository` argument — a canonical git remote URL (homed as an origin identity) or a UUID identifying a local, no-remote repository — instead of inferring the repository from the current working directory, which resolved to the calling drone's own cube and returned a 400. An optional `working_repo_name` sets the repository's short display name; it defaults to the URL's repository segment and is required when `repository` is a local UUID. The server homes one cube per repository, so when the given repository already has a cube the tool reports that existing cube and leaves its directive unchanged rather than overwriting it. The tool result now carries a `result` of `created` or `resolved` so callers can tell a new cube from an already-existing one, and an optional post-create `template` is applied only to a newly created cube, never to an existing repository cube.
